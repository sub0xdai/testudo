Quick Context

Testudo is a Rust-based crypto exchange platform with a comprehensive REST API (/api/v1/), WebSocket real-time streaming, a shadow (paper) trading engine, a risk engine with 8 validation checks + multi-method sizing, and an AI coach pipeline.

The exchange supports both CEX (Binance, Bybit, OKX via a Node.js sidecar on port 3100) and DEX (Hyperliquid via native Rust SDK).

🔑 Key insight: The platform already has agent wallet support for Hyperliquid — cryptographic keypairs that trade on behalf of a user via EIP-712 approval. This is the primary foot-in-the-door for coding agents.

01 Signal Endpoint

Impact
High
Unlocks programmatic trading for all agents
Effort
Low
~3 new files, ~2 modified

The Gap

Today, trading can only be initiated through the browser extension (Alt+X on TradingView → DOM scrape → modal → confirm). There is no programmatic way for an external agent to submit a trade signal. A coding agent working from chart analysis, an on-chain event, or a sentiment signal has no API to act on it.

The Solution

A dedicated signal endpoint that agents call directly, bypassing TradingView entirely:

POST /api/v1/signals
Authorization: Bearer <token>

{
  "symbol": "BTC_USDT",
  "side": "LONG",
  "entry_price": "50000.00",
  "stop_loss": "49000.00",
  "take_profit": [
    { "price": "51500.00", "quantity": "0.25" },
    { "price": "53000.00", "quantity": "0.25" }
  ],
  "exchange_account_id": "uuid",
  "execution_mode": "shadow",           // or "live"
  "reasoning": "RSI divergence 4H + volume spike",
  "source": "agent:hermes_v1.2",        // attribution
  "confidence": 0.72,                   // stored in journal
  "idempotency_key": "uuid"
}

Acceptance Criteria

  • Any agent with valid auth can submit a signal
  • Signal passes through DecisionLoop (never bypasses risk engine)
  • Shadow mode supported for strategy testing
  • reasoning and source fields stored in journal for attribution
  • confidence field stored for future Kelly calibration
  • Idempotency key prevents double-execution
  • Response includes trade_group_id, entry order ID, sizing method, and warnings

02 Agent WebSocket Alerts

Impact
Medium
Real-time awareness for agents
Effort
Low
~2 new files, ~1 modified

The Gap

Agents today have no real-time awareness of exchange state. They must poll REST endpoints to check if an order filled, if a stop-loss triggered, or if a drawdown limit was breached. This is inefficient and slow — an agent may act on stale data.

The Solution

Dedicated WebSocket channels for agent-critical events:

// Agent alert: risk breach
{
  "stream": "agent.alert.550e8400-...",
  "data": {
    "type": "risk_breach",
    "severity": "warning",
    "message": "Daily drawdown at 4.2% — approaching 5% limit",
    "current_drawdown_pct": 4.2,
    "limit_pct": 5.0
  }
}

// Agent execution report
{
  "stream": "agent.execution.550e8400-...",
  "data": {
    "type": "execution_report",
    "trade_group_id": "uuid",
    "order_id": "12345",
    "status": "filled",
    "fill_price": "50000.00",
    "latency_ms": 342,
    "exchange": "hyperliquid"
  }
}

Channels

ChannelEvent Types
agent.alert.{user_id}Risk breaches, drawdown warnings, margin calls, agent wallet expiry
agent.execution.{user_id}Fill confirmations, rejections, latency breakdowns, cancellation reports
agent.order.{user_id}Order lifecycle: placed → partially filled → filled → cancelled
agent.balance.{user_id}Balance snapshots after each fill, daily PnL updates
💡 Why pg_queue makes this cheap: The WebSocket server already subscribes to PostgreSQL LISTEN/NOTIFY channels. The router calls pg_notify('order_events', payload) after every event. Agent alert channels are just additional notification channels — no new infrastructure needed.

03 Journal as Agent Memory

Impact
Medium
Gives agents trading history awareness
Effort
Low-Medium
~2 new files, ~2 modified

The Gap

The journal stores every trade, fill, tag, note, and management decision. The analytics layer computes equity curves, win rates, R-multiples, symbol breakdowns, and time distributions. But an agent can't ask "how did my ETH breakouts perform in Q1?" without parsing raw analytics JSON themselves.

The Solution

Agent Summary Endpoint

GET /api/v1/journal/agent/summary
Authorization: Bearer <token>
Content-Type: application/json

{
  "query": "ETH setups with win rate above 50% last 90 days",
  "timeframe": "90d",
  "format": "llm"          // "json" or "llm" (markdown for LLM context)
}

Response (format: "llm") returns structured markdown with citation-linked trade IDs, setup breakdowns, and actionable insights — ready to feed directly into an LLM context window.

EndpointDescription
GET /journal/agent/summaryStructured summary with filters, LLM-ready or JSON
GET /journal/agent/insightsActionable insights: low WR setups, stop distance issues, session timing
GET /journal/agent/compareCompare two time periods or strategies side by side

Risk-Mitigated Rollout

1
Shadow-first: All agent functionality launches in shadow mode. No real money at risk.
2
Agent-only risk config: Agents get stricter limits than the human user — lower max positions, smaller sizes, tighter drawdown.
3
Journal audit trail: Every agent action recorded with source: "agent:..." for full traceability.
4
Graduated live: Agent graduates after shadow performance meets thresholds (configurable: 50+ trades, >45% WR, positive avg-R).

05 Agent Onboarding Flow

The complete 7-step flow for a coding agent to start trading on Testudo:

Step 1: Auth — Get API Access

# Get SIWE nonce
curl -s https://api.testudo.vip/api/v1/auth/nonce

# Verify signature, get bearer token
curl -X POST https://api.testudo.vip/api/v1/auth/verify-siwe \
  -H "Content-Type: application/json" \
  -d '{"message": "...", "signature": "0x..."}'

# Response → { tokens: { access_token, refresh_token, expires_in: 900 } }

Step 2: Configure Exchange Account

# Hyperliquid (agent wallet path)
curl -X POST https://api.testudo.vip/api/v1/exchanges/agent-wallet/init

# User approves via MetaMask (EIP-712)
curl -X POST .../api/v1/exchanges/agent-wallet/approve \
  -d '{"agent_address":"0x...","signature":"0x...","nonce":1710600000000}'

# Or CEX (API key path)
curl -X POST .../api/v1/exchanges/accounts \
  -d '{"exchange_name":"binance","api_key":"...","secret":"..."}'

Step 3: Set Conservative Risk Config

curl -X PUT .../api/v1/risk-config -d '{
  "account_risk_percent": 0.5,
  "max_risk_amount": 25.0,
  "max_position_size": 0.1,
  "max_leverage": 3,
  "daily_max_drawdown_percent": 3.0,
  "max_open_positions": 2,
  "require_stop_loss": true,
  "min_risk_reward_ratio": 2.0
}'

Step 4: Trade in Shadow Mode

curl -X POST .../api/v1/signals -d '{
  "symbol": "BTC_USDT",
  "side": "LONG",
  "entry_price": "50000.00",
  "stop_loss": "49000.00",
  "take_profit": [{"price":"52000.00","quantity":"1.0"}],
  "execution_mode": "shadow",
  "reasoning": "Testing breakout strategy on 4H",
  "source": "agent:hermes_v0.1",
  "confidence": 0.65,
  "idempotency_key": "550e8400-..."
}'

Step 5: Analyze Journal Performance

# Check shadow performance
curl .../api/v1/journal/agent/summary -d '{"timeframe":"90d","format":"llm"}'

# Get actionable insights
curl .../api/v1/journal/agent/insights

# Compare before/after strategy change
curl .../api/v1/journal/agent/compare -d '{
  "period_a":{"from":"2026-01-01","to":"2026-03-01"},
  "period_b":{"from":"2026-03-01","to":"2026-05-01"}}
}'

Step 6: Graduate to Live

# Same signal, execution_mode: "live"
curl -X POST .../api/v1/signals -d '{
  "execution_mode": "live",
  "reasoning": "Confirmed breakout. Shadow: 58% WR, 1.9 avg R.",
  ...
}'

Step 7: Monitor via WebSocket

const ws = new WebSocket('wss://api.testudo.vip:4000');
ws.send(JSON.stringify({
  method: 'SUBSCRIBE',
  params: ['agent.alert.<user_id>', 'agent.execution.<user_id>'],
  id: 1
}));

ws.onmessage = (event) => {
  const msg = JSON.parse(event.data);
  if (msg.stream.startsWith('agent.alert'))
    console.warn(`⚠️ Alert: ${msg.data.message}`);
  if (msg.stream.startsWith('agent.execution'))
    console.log(`✅ ${msg.data.status}: ${msg.data.fill_price}`);
};

Summary

01 Signal Endpoint
The biggest unlock. Agents can't trade programmatically today. One new route, reuses DecisionLoop entirely.
02 Agent WS Alerts
pg_queue LISTEN/NOTIFY already does the heavy lifting. Adding agent channels is configuration, not architecture.
03 Journal Memory
Rich journal data — 11 chart types, CoachDigest patterns, tag filtering. LLM-ready output gives agents the feedback loop they need.
⏱️ Timelines: All three can be built in ~2 weeks. They build on existing, battle-tested infrastructure. No new databases, no new messaging systems, no new auth flows. They extend what Testudo already does well — risk-managed execution, real-time streaming, and comprehensive journaling — into the agent domain.
